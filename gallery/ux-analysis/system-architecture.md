# وثيقة بنية النظام

بالتأكيد، إليك وصف تفصيلي لبنية نظام CRM المقترح:

## بنية نظام إدارة علاقات العملاء (CRM)

يعتمد هذا النظام على مجموعة من التقنيات الحديثة والممارسات الموصى بها لتقديم تطبيق ويب فعال وآمن وقابل للتطوير. تم تصميمه بواجهة عربية تدعم العرض من اليمين إلى اليسار (RTL) بشكل كامل.

---

### 1. معمارية النظام (System Architecture)

يتبع النظام معمارية متعددة الطبقات (Multi-layered Architecture) التي تفصل بين الاهتمامات المختلفة للتطبيق، مما يسهل عملية التطوير والصيانة.

#### الطبقات (Layers):

*   **طبقة العرض (Presentation Layer):**
    *   **الوصف:** هذه هي الطبقة التي يتفاعل معها المستخدم مباشرة. هي مسؤولة عن عرض واجهة المستخدم (UI) وتقديم البيانات للمستخدم واستقبال مدخلاته.
    *   **التقنيات:**
        *   **Blade Templates:** محرك قوالب Laravel القوي لإنشاء صفحات HTML ديناميكية.
        *   **Tailwind CSS:** إطار عمل CSS يعتمد على الأدوات المساعدة (Utility-First) لبناء تصميمات مخصصة وسريعة الاستجابة. تم تكوينه ليدعم واجهة RTL بشكل كامل.
        *   **Alpine.js:** إطار عمل JavaScript خفيف الوزن لإضافة التفاعلية إلى الواجهات دون الحاجة إلى أطر عمل ضخمة.

*   **طبقة المنطق (Business Logic Layer):**
    *   **الوصف:** هذه هي "عقل" التطبيق. تحتوي على القواعد والعمليات التي تدير كيفية إنشاء البيانات ومعالجتها وتخزينها.
    *   **التقنيات:**
        *   **Laravel Controllers:** تستقبل طلبات HTTP من طبقة العرض، وتنسق العمليات اللازمة لتلبية هذه الطلبات.
        *   **Laravel Models (Eloquent ORM):** تمثل الكيانات الرئيسية في النظام (مثل `Customer`, `Product`) وتتفاعل مع قاعدة البيانات لتنفيذ عمليات CRUD (إنشاء، قراءة، تحديث، حذف).

*   **طبقة البيانات (Data Layer):**
    *   **الوصف:** مسؤولة عن تخزين واسترجاع البيانات بشكل دائم.
    *   **التقنيات:**
        *   **SQLite:** قاعدة بيانات خفيفة الوزن تعتمد على ملف واحد، مثالية للتطبيقات المتوسطة وسهولة الإعداد والنقل. يتفاعل معها النظام عبر Eloquent ORM الخاص بـ Laravel.

#### تفاعل الطبقات:

عندما يطلب المستخدم صفحة ويب (مثل عرض قائمة العملاء)، يبدأ التفاعل في **طبقة العرض**. يتم إرسال طلب HTTP إلى **طبقة المنطق**، حيث يحدِّد موجِّه Laravel (Router) أي `Controller` يجب أن يعالج الطلب. يقوم الـ `Controller` باستخدام الـ `Model` المناسب (مثلاً `Customer` model) لجلب البيانات من **طبقة البيانات** (قاعدة بيانات SQLite). بعد الحصول على البيانات، يقوم الـ `Controller` بتمريرها إلى `Blade Template` في **طبقة العرض**، والتي تقوم بعرض البيانات بتنسيق HTML وإرسالها مرة أخرى إلى متصفح المستخدم.

### 2. قاعدة البيانات (Database Schema)

تم تصميم مخطط قاعدة البيانات ليكون مرنًا وفعالًا، مع التركيز على العلاقات المنطقية بين الوحدات المختلفة.

#### الجداول الرئيسية:

*   `customers` (العملاء): يخزن معلومات العملاء مثل الاسم، البريد الإلكتروني، الهاتف، والعنوان.
*   `products` (المنتجات): يحتوي على تفاصيل المنتجات مثل الاسم، الوصف، رمز SKU، والسعر.
*   `invoices` (الفواتير - المبيعات): يسجل كل عملية بيع، ويرتبط بالعميل والمنتجات المباعة.
*   `purchases` (المشتريات): يسجل عمليات الشراء من الموردين، ويرتبط بالمورد والمنتجات المشتراة.
*   `warehouses` (المخازن): يدير مواقع تخزين المنتجات المختلفة.
*   `employees` (الموظفين): يخزن بيانات الموظفين وصلاحياتهم.
*   `expenses` (المصروفات): يسجل جميع نفقات الشركة التشغيلية.

#### العلاقات (Relationships):

*   **One-to-Many (واحد-إلى-متعدد):**
    *   العميل (`Customer`) الواحد يمكن أن يمتلك فواتير مبيعات (`invoices`) متعددة.
    *   المخزن (`Warehouse`) الواحد يمكن أن يحتوي على منتجات (`products`) متعددة.
    *   فئة المنتج (`Category`) الواحدة يمكن أن تضم منتجات (`products`) متعددة.

*   **Many-to-Many (متعدد-إلى-متعدد):**
    *   الفاتورة (`Invoice`) الواحدة يمكن أن تحتوي على منتجات (`products`) متعددة، والمنتج الواحد يمكن أن يكون جزءًا من فواتير متعددة. يتم تحقيق هذه العلاقة عبر جدول وسيط يُسمى `invoice_items`.
    *   عملية الشراء (`Purchase`) الواحدة يمكن أن تشمل منتجات (`products`) متعددة، والمنتج الواحد يمكن أن يكون في عمليات شراء متعددة. يتم تحقيق ذلك عبر جدول وسيط يُسمى `purchase_items`.

### 3. تدفق الطلبات (Request Lifecycle)

يمر كل طلب HTTP بسلسلة من الخطوات المنظمة داخل إطار عمل Laravel:

1.  **طلب الصفحة:** يقوم المستخدم بطلب عنوان URL من المتصفح (مثلاً `https://crm.app/invoices`).
2.  **التوجيه (Routing):** يستقبل خادم الويب الطلب ويمرره إلى Laravel. يقوم ملف `routes/web.php` بالبحث عن المسار المطابق ويوجهه إلى الـ `Controller` المحدد.
3.  **استقبال الطلب في الـ Controller:** يتم تنفيذ الدالة (Method) المحددة في الـ `Controller` (مثلاً `InvoiceController@index`).
4.  **التفاعل مع الـ Model:** يقوم الـ `Controller` باستدعاء الـ `Model` (مثلاً `Invoice::with('customer')->get()`) لطلب البيانات من قاعدة البيانات.
5.  **تنفيذ استعلام قاعدة البيانات:** يقوم Eloquent ORM بترجمة هذا الطلب إلى استعلام SQL فعال وتشغيله على قاعدة بيانات SQLite.
6.  **معالجة النتائج:** تقوم قاعدة البيانات بإرجاع النتائج إلى الـ `Model`، والذي يحولها إلى كائنات PHP (Objects) منظمة.
7.  **إرجاع الـ View:** يقوم الـ `Controller` بتمرير هذه الكائنات إلى `Blade view` باستخدام دالة `view()`.
8.  **عرض الصفحة:** يقوم محرك Blade بمعالجة القالب، وإدخال البيانات الديناميكية، وإنشاء ملف HTML النهائي الذي يتم إرساله كاستجابة (Response) إلى متصفح المستخدم ليتم عرضه.

### 4. الأمان (Security)

تم تطبيق إجراءات أمان متعددة المستويات لحماية النظام من التهديدات الشائعة:

*   **المصادقة (Authentication):** استخدام حزمة **Laravel Breeze** لتوفير نظام تسجيل دخول وتسجيل مستخدمين آمن ومتكامل، مع ميزات مثل إعادة تعيين كلمة المرور والتحقق من البريد الإلكتروني.
*   **الحماية من CSRF (CSRF Protection):** يقوم Laravel تلقائيًا بإنشاء رمز (Token) فريد لكل جلسة مستخدم. يجب إرسال هذا الرمز مع كل طلب (POST, PUT, DELETE) لحماية التطبيق من هجمات تزييف الطلبات عبر المواقع.
*   **منع حقن SQL (SQL Injection Prevention):** يستخدم Eloquent ORM ربط المعلمات (PDO Parameter Binding) بشكل افتراضي، مما يمنع بشكل كامل هجمات حقن SQL.
*   **التحقق من صحة المدخلات (Input Validation):** يتم التحقق من جميع البيانات الواردة من المستخدم عبر `Form Request Validation` في Laravel، مما يضمن أن البيانات تتوافق مع القواعد المحددة قبل معالجتها.
*   **الحماية من XSS (XSS Protection):** يقوم محرك Blade تلقائيًا بعمل `escape` لجميع البيانات التي يتم طباعتها باستخدام صيغة `{{ $variable }}`، مما يمنع حقن النصوص البرمجية الخبيثة في صفحات الويب.

---

### 5. الأداء (Performance)

لضمان تجربة مستخدم سريعة وسلسة، تم تطبيق الاستراتيجيات التالية:

*   **فهرسة قاعدة البيانات (Database Indexing):** تم إضافة فهارس (Indexes) إلى الأعمدة التي يتم الاستعلام عنها بشكل متكرر في قاعدة البيانات (مثل المفاتيح الأجنبية `customer_id` والحقول القابلة للبحث). هذا يسرع بشكل كبير من عمليات قراءة البيانات.
*   **تحسين الاستعلامات (Query Optimization):** استخدام تقنية **التحميل المسبق (Eager Loading)** عبر دالة `with()` في Eloquent لحل مشكلة "N+1 Query Problem"، مما يقلل عدد الاستعلامات المنفذة بشكل كبير عند عرض القوائم ذات العلاقات.
*   **استراتيجية التخزين المؤقت (Caching Strategy):** يمكن استخدام واجهة التخزين المؤقت في Laravel (`Cache Facade`) لتخزين نتائج الاستعلامات المكلفة أو البيانات التي لا تتغير بشكل متكرر (مثل إعدادات التطبيق أو التقارير اليومية).
*   **تحسين الأصول (Asset Optimization):** استخدام **Vite** لتجميع وضغط ملفات CSS و JavaScript. عند تشغيل أمر `npm run build`، يقوم Vite بإنشاء ملفات محسّنة ومصغّرة للاستخدام في بيئة الإنتاج، مما يقلل من وقت تحميل الصفحة بشكل ملحوظ.
